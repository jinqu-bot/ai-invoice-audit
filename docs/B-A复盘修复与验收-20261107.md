> ⚠️ **本文是历史记录，其中数字（如 40/40、58/58、55/60）已作废，不再作为现行口径引用。** 现行只有三个：规则 60/60、识别 44/50（544/550 = 98.9%）、端到端 56/60（93.3%），见 `docs/评测口径总表.md`。

## 问题与处理

未配置视觉模型时，上传仍会由 mock-vlm 按文件摘要选择固定样例。这能验证上传、审核流程，不能读取真实票面。旧版本又把模拟号码写入无来源区分的查重台账，造成“原票变成别人的打车票且已报销”的误导。

- 上传页从健康接口读取实际配置来源；模拟状态下按钮明确写“开始模拟审核（非票面识别）”。
- 批次、单票卡片、详情、历史列表展示记录自身 provider；模拟字段、置信度、轨迹均明确是演示。看板现有固定统计也加演示提示。
- 新增 audit_history，以 (source, invoice_number) 为联合主键。模型来源仅查 openai-compat；mock-vlm 只查 mock-vlm 和 fixture。演示号码与模型号码互不覆盖、互不触发查重。
- 原 reimbursements 表不删除、不清空。可关联到既有批次来源的旧记录按来源复制；无法确认来源的记录隔离为 legacy-unknown，不参与自动查重。旧审核结果保留，按当时批次来源标识；不会伪造重新识别结果。
- 报销人缺失显示“未登记”；R1 表述为与既往审核记录号码重复，明确审核记录不证明实际报销完成。模拟重复结论明确与真实报销无关。
- POST /api/batches 在启动后台线程前持久化 processing 批次，避免立即 GET /results 得到 404。线程启动失败落库为 failed，发送终止事件，不无限等待。
- 保持 202 上传协议，结果统计继续以 /results 为准，SSE 用于通知与进度。保留原上传预览、删除、预检、重试、失败原因和 missing_fields 展示。
