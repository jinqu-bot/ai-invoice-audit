## 五、下午补的两件事（15:00–19:30）

### 1. 模型自己决定查什么（`6a4e463`）

评分表里「Agent/工作流设计 8%」考的是**规划、工具调用、自主决策**，
「MCP/工具集成 4%」认 MCP **或 Function Calling**。我们原来只有固定流水线（if-else 短路）——
"AI 自己决定先干什么"这件事，我们**拿不出证据**。

做法：三个真工具交给模型，让它自己选、自己排顺序。

| 工具 | 落到哪 | 是不是真的 |
|---|---|---|
| `check_duplicate` | `history.find`（真 SQLite 台账） | 真 |
| `search_policy` | `policy_qa.retrieve`（真制度库） | 真 |
| `get_threshold` | `rules.LIMITS`（真配置） | 真 |

**三条硬约束（这是这一层的良心）：**

1. **不改结论**。只出轨迹；这张票 pass 还是 reject，仍由规则引擎算。
2. **没有真模型就 503**。模拟模型是"钉住输出"的替身，让它假装规划等于演。
3. **模型不调工具就退回固定顺序，并标 `by=fallback`**。前端显式标黄："模型未给出工具调用 · 已退回固定顺序"。
   ——否则就是把兜底顺序包装成"AI 在规划"，那是唬评委。

**线上实测**（`verification/agent-plan-live.json`，真模型）：

```
规则引擎：reject（R0 + R3 + R4）
模型自选：查重 → 取费用上限 → 检索制度条款（3 步，全部 by=model，fallback=false，5.4 秒）
模型判断：该驳回——购买方是个人「魏瀚青」，《差旅费管理办法》第 8 条要求抬头与公司一致……
结论是否被改：未变 ✓
```

**最值得讲的一点**：模型自己选的顺序和它给出的理由，**和规则引擎的结论撞上了**
（它独立查到第 8 条、算出 4748 没超 5000）。但它**漏了 R4 超期**——它没想起来查时限。
这恰好说明为什么结论必须由规则引擎出：**模型会漏，规则不会漏。这一层只负责"想怎么查"，不负责"最后怎么判"。**

```
/api/health → {"recognition_provider": "openai-compat"}   ← 全绿
实际调用   → HTTP 402 Insufficient Balance                  ← 已经炸了
```

**因为健康检查只看"有没有配 key"，配了就报 `openai-compat`。**
账户没钱、key 失效、被限流，它一律说一切正常——这和我们一直标榜的"不装"是矛盾的。

已修：`/api/health` 现在多带 `model_ok` / `last_ok_at` / `last_error` / `consecutive_failures`，
初始状态就是 `model_ok=false`（没调用过就不给绿灯）。不探活（探活要花钱），
只在真实调用失败时记一笔。演示前自检那条命令也改了：**要同时看 `model_ok`，不能只看 `recognition_provider`。**
