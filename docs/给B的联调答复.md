我的单元测试全绿没发现，因为那批测试只测抽取逻辑，没走路由的 `response_model` 校验。这是我这轮的疏漏。

**修法：加 `warn`，不是把 `warn` 改掉。** 理由——转人工不是出错，是「跑完了但拿不准」，语义上就该和 `error` 分开，而且答辩时这个状态是加分项，不该被合并。

已改：

| 位置 | 改动 |

| `schemas.py` | `TraceStatus` 增加 `warn`，注释写清它不是错误 |
| `types.ts` | 同步增加 `warn` |
| `format.ts` | `TRACE_STATUS_META` 增加 `warn: { label: "待确认", dot: "bg-amber-400" }` |
| `tests/test_contract.py` | 新增回归测试：把阈值拉到 1.0 强制走转人工，断言详情接口 200 且确实带 `warn` |

### 6. 422 响应格式不统一 —— 你说对了

原来只接了 `HTTPException`，`RequestValidationError` 没接，缺字段这类错误会吐 FastAPI 原生结构，你按 `code/message` 解析会拿到空。

**已补统一处理器**，422 现在长这样，比别的多一个 `details`：

```json
{
  "code": "VALIDATION_ERROR",
  "message": "q：Field required",
  "details": [{ "field": "q", "reason": "Field required" }]
}
```

`details[].field` 是业务字段名（已经剥掉 `body` 那层），可以直接定位到表单里哪个格子。

### 补充：没有 key 时，怎么验证各条分支

C 今天推了两张非发票图片到 `backend/data/samples/`，但**拿它们跑 mock 证明不了任何事**——mock 不看图片内容，它的输出只跟图片指纹有关。所以「拿一张订单截图跑 mock，看它能不能认出不是发票」这件事，本来就是假的。

想验证某条分支，用 `MOCK_VARIANT` 把 mock 的返回值钉死：

```bash
# backend/.env
MOCK_VARIANT=non_invoice     # 钉在"这不是发票"，用来验转人工 + R0
# MOCK_VARIANT=0 / 1 / 2     # 钉在任一张样例票，结果稳定，方便反复联调
# 留空                        # 按图片指纹取样，默认行为
```

实测 `MOCK_VARIANT=non_invoice` 上传一张图：

```
verdict=manual  manual_review=True  hit_rule_codes=R0  provider=mock-vlm
missing_fields=invoice_number,invoice_date,seller_name,buyer_name,amount_incl_tax
trace=error,error,warn
```

**这是分支验证工具，不是识别能力**，报告里我也会这么写。换成真 key 之后这个开关自动失效。
