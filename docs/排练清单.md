## 一、这次排练要回答的四个问题

1. **5 分钟够不够？** 每幕预算 vs 实测，差多少，砍哪句。
2. **哪一幕会卡？** 卡在哪一步——上传？等结果？找按钮？念台词？
3. **崩了能不能救？** 断网、模型挂、页面刷不出来，主讲人知不知道下一步说什么。
4. **材料能否进入后续制作？** 讲稿和截图是否脱敏、口径是否一致；视频规格留待之后制作时验收，本次不录制。

> 四个问题里，**第 3 个最重要**。前两个影响观感，第 3 个决定生死。

## 六、破坏性演练（**这一轮最值钱，别跳**）

正常演一遍只证明"顺利时能演"。下面 7 个故障，一个一个注进去，看主讲人接不接得住。

| # | 怎么造 | 期望表现 | 主讲人该说什么 | 过了吗 |
|---|---|---|---|---|
| 1 | 上传时**拔网线 / 关 Wi-Fi** | 浏览器连接失败不等于后台批次失败；已有批次可在恢复网络后查询，页面不白屏 | "当前浏览器连不上服务，先讲已加载页面；恢复后按原批次核对，不盲目重传" | |
| 2 | 上传一个**坏的 jpg**（把 txt 改名成 .jpg） | 记录实际拦截层、文件名和错误信息；区分部分失败和全部失败 | 有成功项说"坏文件单独列出，其余成功项在这里"；全失败说"本批没有成功结果" | |
| 3 | 连传**两张同一张票** | 第二张先命中 R1 并短路 | "这是重复报销，查重第一条就拦住了，后面不再查" | |
| 4 | 复核时**不勾选**"已核对原图"就提交 | 被拦住，有提示 | "我们不让人随手改判，必须先核过原图" | |
| 5 | `/ask` 问一个**制度里没有**的问题（如"年会抽奖怎么报"） | 明确答"制度里没有相关条款"，核对实际来源标记 | "这个问题没有适用条款，不生成一个假限额，需要咨询财务" | |
| 6 | 仅由 A 在受控演练窗口或隔离实例注入模型 key 故障，再请求模型旁路 | 明确返回不可用错误并可恢复；不能用缓存成功冒充模型恢复 | "本次模型请求不可用，旁路环节先跳过，已有规则结论保持原样" | |
| 7 | 结果页**按 F5 刷新**（SSE 断） | 结果还在（走 `/results` 兜底） | "流断了不影响结论，后端已经存下来了" | |

> 第 6 条需 A 的账号权限，当前未执行。演练前记录恢复方法，结束**恢复原配置和服务**，核对健康状态，并以一次真正调用模型的最小请求确认恢复；不把密钥写进记录。
> 每一条失败都记下来：是系统的锅，还是主讲人接不住？**两种都要修，修法不同。**
> 独立技术预检的结果单独保存；主讲人是否能接住必须在三人排练中验收，不能因接口测试通过就给本表全部打勾。

## 七、复盘（15 分钟，别边演边改）

回答四个问题，写下来：

1. **超时了吗？** 超了几秒？砍哪句话最不心疼？
2. **哪一幕最冷？** 冷在等结果，还是在找按钮，还是在念台词？

4. **材料是否适合后续制作？** 讲稿是否超长？截图是否清楚且脱敏？录像验收本次不执行。

**然后只改这三类**：① 台词太长（砍）② 操作顺序不顺（调）③ 故障话术没有（补）。
**不改功能、不改代码**——今天不是写代码的日子。

## 十、公开材料的三个合规点（录像排除本次执行）

1. **那张真发票上有第三方的姓名和税号**，不朗读身份字段，不放进公开材料。
   > **已经有替代品了**：`backend/data/demo/demo_personal.jpg`
   > —— 我们自己生成的"个人抬头 + 超期"样票，购买方写的是「个人用户」（编的），没有税号。
   > 既有验收记录中命中 **R3 + R4，结论 reject**，金额为 4748；本次仍要按实际识别结果讲。
   > **样票税率是 6%，原真票材料是 13%，台词不能照搬。** 只说“个人抬头”，金额、日期、税率都核对本次图片与响应。
   >
   > 生成命令：`python backend/scripts/make_demo_invoice.py`
   >
   > **用法**：本次技术预演和公开材料使用生成样票；以后录制也用样票。现场是否展示真票由持有人确认。
   > 如果被问“这是真票吗”，使用样票时答：“这张是我们生成的演示样票，避免公开第三方姓名税号；识别仍按输入图片运行。”不要把样票说成真票。
   > —— 这个回答本身就是加分项。
2. **不要说"已完成真实报销审批"**。系统做的是审核建议 + 留痕，不是付款。
3. **改判理由不许写"已补开发票、财务确认"**。没这回事。用"联调测试：验证改判留痕，不代表真实报销审批"。
