## B1：未命中缓存的真实 SSE

使用全新生成的合成样票 `SSE_COLD_20261114.jpg`，票号与图片均新生成。没有执行生产复位，也没有清服务器缓存；通过最终卡片的 `cached=false` 确认本张实际调用模型，`provider=openai-compat`、`model=deepseek-flash`。这证明的是一次**识别缓存未命中**，不是模型服务器进程的冷启动。

批次：`B20261114-001`。以下四个时间点统一从客户端开始 `POST /api/batches` 计时：

| 指标 | 本次实测 | 原始响应/事件 |
|---|---:|---|
| POST 返回 | **2.35154 秒** | HTTP `202`，`status=processing` |
| SSE 首个事件到达 | **2.76944 秒** | `hello`，`replay=false` |
| 第一张票出结果 | **4.85432 秒** | `invoice_done` |
| 整批完成 | **4.85447 秒** | `batch_done` |

单独从建立 SSE 请求开始算，首事件为 0.41784 秒。后端报告本批处理耗时 `2333ms`，卡片报告 `2329ms`；它们与客户端从上传开始的 4.85447 秒起点、覆盖范围不同，不能互相替代。

SSE 的 `hello/batch_start/invoice_start` 在约 2.77 秒到达，规则轨迹随后到达，结果在约 4.85 秒到达。由此可以确认此次流在结果完成前已建立并传递开始事件。不能据此声称所有模型 token 或每个内部思考步骤都逐字实时输出。

最终：1 张发票、0 个失败文件、结论 `reject`，命中 `R0 + R3 + R4`，金额 4748.00，置信度 0.2。完成后健康检查为 `model_ok=true`、连续失败 0。

这是一个样本、一次网络条件下的实测，不是平均值或性能保证。现场仍应准备超过 5 秒时的解释话术，按屏幕标记分别说明“本次调用模型”“缓存命中”或“回放”。

证据：[B1 原始时间戳、SSE 与结果](../_local/acceptance-20261114/B1-cold-sse.json)。
